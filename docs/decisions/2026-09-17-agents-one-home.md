# Один дом для агентов: сверка library/agents с refract

Дата: 2026-09-17. Шаг 1 плана (`SPEC.md` §10).

## Что сверялось

`library/agents` в facet (28 пакетов) против `library/agents` в `../refract` (13 пакетов;
refract заморожен, последний коммит 2026-07-28). Сравнение с `--strip-trailing-cr`: рабочая
копия refract лежит с CRLF, и без этого «различались» все файлы.

## Результат

Семь пакетов совпадают побайтно. Шесть расходятся, и во всех шести новее facet:

| пакет | что изменилось после расхождения |
|---|---|
| `confluence_publisher` | публикация через `tools/confluence_publish.py`, а не MCP-конвертацией |
| `illustrator` | figgybanana CLI вместо MCP paperbanana; порт `article`, не `design_doc` |
| `requirements_writer` | ссылки на источник у каждого требования; язык результата — из источников |
| `requirements_fact_checker` | правит ссылки на источник на месте |
| `requirements_critic` | сверяет ссылки, а не считает их; вывод — в «Assumptions» |
| `source_finder` | `mcp:pdf-reader` — искатель без PDF объявлял аспект непокрытым |

Из refract забирать нечего; источник правды по агентам — `library/agents` в facet.
`refract/claude-agents/` пуст.

## Сгенерированное

`emit_all` в чистый каталог даёт побайтно те же 28 файлов, что лежат в `.claude/agents`:
ручных правок в сгенерированном нет. Это и есть критерий готовности шага.

## Профили через `skills:`

Поле `skills:` во фронтматтере агента подгружает `.claude/skills/<имя>/SKILL.md` в контекст
при запуске. Два свойства рантайма определили форму:

- **несуществующий профиль пропускается молча** — предупреждение только в debug-журнале,
  агент стартует без контракта. Поэтому `emit_agents` проверяет каждый названный профиль на
  диске и падает, если его нет; `tests/test_workflows.py` проверяет то же по сгенерированному;
- **профиль с `disable-model-invocation: true` не подгружается.** В профилях этого поля нет,
  и тест это держит. `user-invocable: false` подгрузке не мешает и убирает профиль из списка
  слеш-команд.

Имена — `<тип>-profile`, а не `<тип>`, как было записано в SPEC §6 до этого шага: сохранённые
воркфлоу `.claude/workflows/<имя>.js` уже занимают имена скиллов `solution-design`,
`explainer-article`, `attn-figures`, и `requirements.js` из шага 5 занял бы `requirements`.
Проектный скилл перекрывает одноимённый, и профиль подменил бы точку запуска конвейера.

Объявлено: `requirements-profile` у писателя, корректора и критика требований;
`solution-design-profile` у дизайнера и его критика. Содержимое профилей — скелет из
обязательных разделов §6, контракт остаётся в промптах до шага 3.
