# Profile: requirements

This is the profile of one document type. The writer, the corrector and the critic of a
requirements document all receive this file at spawn, so whatever it says binds all three
at once. It is being filled in step by step (facet SPEC §6, plan step 3); the sections
below that still say so are carried, for now, by each agent's own instructions.

## Purpose and reader

A requirements document consolidates what the client's source material (transcripts,
briefs, RFPs, chats, spreadsheets) establishes into one document a delivery team can build
from and the client can check against their own words.

## Section contract

Carried by the agents' own instructions until this profile takes it over.

## Critic checklist

Carried by the critic's own instructions until this profile takes it over.

## Gate rules

Carried by the workflow script until this profile takes them over.

## Exemplar

No exemplar skeleton yet (plan step 4).

## Level

3 — a saved Dynamic Workflow (`requirements.js`), extract fan-out and a corrected,
criticised writing loop.

## Output language

The language of the source material, not of these instructions and not of the order,
unless the order says otherwise. The people whose words the document consolidates must be
able to check it against what they said.
