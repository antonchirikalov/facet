# facet — спецификация проекта

Версия 0.1 · 2026-09-17 · статус: принята к работе

## 1. Что это

facet — дом для практики подготовки документов предпроектного и проектного анализа
(требования, технический дизайн, дискавери, исследования и статьи, разовые документы)
на Dynamic Workflows Claude Code с собственными агентами.

Это прямой наследник collimator: тот же репозиторий, та же история git, те же скрипты,
агенты и инструменты. Изменилось назначение. collimator задумывался компилятором
`pipeline.yaml` в скрипты воркфлоу; компилятор не был достроен, а скрипты написаны руками,
и это признано состоянием, а не этапом. facet принимает это как данность и добавляет то,
чего не было ни в одном из предшественников: слой содержания — профили типов документов,
эталоны, каталог типов с уровнями тяжести и точку входа «хочу документ типа X».

Линия проектов: prism → spectra → loom → refract → collimator → facet. Пять оркестраторов
переписаны за три месяца; шестой не пишется.

## 2. Решения, принятые до начала работы

**Р1. Оркестратор — сохранённые Dynamic Workflows, написанные руками.** По одному скрипту
на тяжёлый конвейер. Компилятор скриптов не строится. Генерируются только определения
подагентов (`collimator/emit_agents.py`: `library/agents/*` → `.claude/agents/*.md`).

**Р2. В репозитории не пишется код оркестрации.** Ни планировщика, ни леджера, ни рантайма,
ни машины состояний, ни компилятора. Это единственная защита от шестой итерации. Питон
допускается только как инструмент-линейка, вызываемый агентом (см. §5).

**Р3. Качество документа задаёт форма круга правки, а не оркестратор.** Доказано
ретроспективой collimator (`docs/dynamic-workflows-retrospective-2026-08-17.md`): девять
дефектов конвейера против четырёх дефектов платформы, токены сожгли первые. Уроки круга
обязательны для всех конвейеров: корректор перед критиком; ведомость замечаний по номерам
с ответом писателя на каждый; улика вместо вердикта (агент выписывает проверенное, а не
объявляет «всё в порядке»); детектор полки; незакрытое пишется явно.

**Р4. Число агентов задаёт текст скрипта.** Роли фиксированы вызовами `agent()`; веер
ограничен потолком из `cfg`; круги — `maxRounds` и полка. Верхняя граница прогона считается
арифметически до запуска. Модель в этом решении не участвует.

**Р5. Между конвейерами и стадиями передаются только файлы и `args`.** Переменные скрипта
несут управление (пути, числа, вердикты); файлы несут содержание.

**Р6. Всё детерминированное решает питон, а не модель.** Длина, штампы, пустые разделы,
ссылки, номер круга, перечисление каталога, занятость каталога.

**Р7. Один хук — ревизор, не управление.** `SubagentStop → tools/stop_audit.py` остаётся.
Блокирующие хуки (`PreToolUse`, `Stop`) не вводятся: порядок держит скрипт.

**Р8. Данные клиентов в репозиторий не попадают.** Эталоны хранятся скелетами, пути к
настоящим документам — в `exemplars.local.yaml` под `.gitignore`.

## 3. Три уровня тяжести

Тип документа определяет уровень; уровень определяет, что запускается.

| Уровень | Что | Как исполняется | Агентов |
|---|---|---|---|
| 1 | Разовые: памятка, повестка, письмо, TCO, обзор решения, бриф | обычная сессия + профиль + подагенты писатель/критик, гейт напрямую | 2–3 |
| 2 | Профильные с кругами: gap-анализ, роли и сценарии, вопросы к архитектуре | скилл `/doc <тип> <папка>` в сессии, 1–2 круга критика | 3–6 |
| 3 | Тяжёлые конвейеры: требования, дизайн, статья/исследование, иллюстрации | сохранённый DW-скрипт | 10–20 |

Правило перевода: делал документ типа руками второй раз — пиши профиль (уровень 1→2);
профилю нужны сверка с источниками и больше двух кругов — он идёт в DW-скрипт (2→3).

## 4. Конвейеры уровня 3

Четыре скрипта в `.claude/workflows/`:

| Скрипт | Вход | Выход | Состояние |
|---|---|---|---|
| `requirements.js` | папка `input/` с документами клиента | `reqs/_requirements.md`, `_traceability.md`, `_open_questions.md`, `_unresolved.md` | **написать** (по образцу `solution-design.js`) |
| `solution-design.js` | `reqs/_requirements.md` | `design/_solution_design.md` + иллюстрации | есть |
| `explainer-article.js` | заказ в одну фразу | статья, источники, записи кругов | есть |
| `attn-figures.js` | документ с плейсхолдерами | PNG + манифест | есть |

Форма `requirements.js`: `extract` (по агенту на документ, параллельно, потолок
`cfg.maxSources`) → `write` (писатель → корректор → критик, до `cfg.maxRounds`, полка) →
выдача в `reqs/`. Человек читает `reqs/` и запускает `/doc-design`.

Общая шапка каждого скрипта:

```javascript
const cfg = {
  maxSources: 8, extractWorkers: 4,
  maxRounds: 3, correctors: true,
  candidateModels: ['sonnet', 'opus'],
  ...args.config,
}
```

Общая часть (cfg, `task()`, схемы вердикта и селектора, команды гейта, ревизия) копируется
между скриптами — `import()` запрещён; `tests/test_workflows.py` следит, чтобы копии не
разъехались.

## 5. Питон — линейка, не прораб

`tools/`: `gate.py` (схема, разделы, объём прозы, штампы из файла, пустые заголовки),
`rounds.py` (ведомость кругов, полка, «чем продолжать»), `listing.py` (что реально лежит),
`busy.py` (занят ли каталог), `newrun.py` (имя каталога прогона), `snapshot.py`,
`stop_audit.py` (хук-ревизор), `confluence_publish.py`. Всё вызывается агентом внутри
воркфлоу или сессией на уровнях 1–2. Новые инструменты допускаются, если они измеряют, а не
управляют. Первый кандидат: правило гейта «в каждой строке таблицы требований есть ссылка на
источник» под профиль `requirements`.

## 6. Профили типов документов

Профиль — скилл `.claude/skills/<тип>-profile/SKILL.md`, предзагружаемый в агентов через поле
`skills:` во фронтматтере (писатель и критик одного типа получают один и тот же профиль).
Суффикс `-profile` обязателен: сохранённые воркфлоу `.claude/workflows/<имя>.js` уже занимают
имена скиллов `solution-design`, `explainer-article`, `attn-figures`, и проектный скилл
`<тип>` перекрыл бы точку запуска конвейера (`docs/decisions/2026-09-17-agents-one-home.md`).
Несуществующий профиль рантайм пропускает молча, поэтому его существование проверяет сборка
агентов; `disable-model-invocation: true` в профиле запрещён — такой скилл не подгружается.

Обязательные разделы профиля: назначение и читатель; контракт разделов (структура, что
обязательно, что запрещено); чеклист критика (что проверять, в порядке важности); правила
гейта с порогами; ссылка на скелет эталона; уровень тяжести; язык результата (правило: язык
источников, не промпта).

Первые три профиля: `requirements` (контракт уже написан в промпте критика — вынести),
`solution-design` (из промпта дизайнера), `gap-analysis` (первый профиль уровня 2).

## 7. Эталоны

`exemplars/<тип>/skeleton.md` — заголовки, по одной обезличенной строке таблицы, пометки
«что здесь обязательно и почему». `exemplars/<тип>/why.md` — почему выбран именно этот
документ. Один эталон на тип, выбранный, а не накопленный. `exemplars.local.yaml`
(`.gitignore`) — тип → путь к настоящему документу на диске; агент читает полный эталон,
если путь доступен.

## 8. Стандарт клиентской папки

Как сложилось в реальных папках, зафиксировать в `docs/run-layout.md`:

```
<клиент>/
  input/                    исходники клиента как пришли
  reqs/                     требования: _requirements.md, _traceability.md, _open_questions.md
  design_<дата>/            дизайн: _solution_design.md, illustrations/, logs/, prompts/
  estimates/
  illustrations/
  <разовые документы>.md    уровень 1–2, рядом
```

## 11. Чего в проекте нет и не будет

Веб-интерфейс, REST/WS API, каталог блоков, реестр типов с проверкой рёбер, собственный
рантайм, компилятор скриптов, машина состояний с турникетом. Первые пять — ценность для
чужого пользователя, которого нет. Последние два — код оркестрации (Р2).

## 12. Отложенные опции

Записаны, чтобы не изобретать заново; не входят в план.

- **Турникет**: сессия-прораб + `next.py` + хуки `PreToolUse`/`PostToolUse`/`Stop`.
  Убирает носильщиков, каскадный перезапуск, даёт человека посреди прогона. Это код
  оркестрации; рассматривается, только если доля носильщиков в прогонах превысит порог.
  **Порог: 50 % вызовов подагентов за прогон** (`gate-runner` + `file-copier`, считать по
  `logs/stop-audit.jsonl`). Замер 2026-09-18, статья про трансформер, четыре запуска:
  31 из 84, то есть 37 %; за ними 73 расписки инструментов — носильщик уже везёт две-три
  команды за вызов.
- **Пробник хуков** (0,5 ч): проверить блокировку кодом 2 у `PreToolUse(Agent)` и `Stop`,
  `additionalContext` у `PostToolUse`. Результат — в `docs/decisions/`.
- **Реестр цитат** `Q-…` и пары «строка → цитата» для корректора требований — линейка
  (Р6), добавляется после того, как профиль `requirements` заработает.
